autonomy-table-chosen

      
L0text onlyno tools
L1per-call approveuser approves each tool call
L2auto read-onlyapproves writes and exec
L3sandboxed execapproves network writes
L4full plan within budgetpauses on budget or error
L5self-directed with checkpointcheckpointed every N steps; autonomy cannot be raised by the agent itself

      
Other Nexus autonomy versions disagree on L5 (god-mode / self-elevation / modify-other-agents). Those versions are NOT used here; see compare spec table. No content filter, refusal scanner, or moderation scanner is added; the only controls are the ones in this table, budgets, sandbox, approval inbox, and owner-set autonomy.

JSON for a simple status handoffWasteful, not blocked — but wrong choice: it costs more tokens and context for no gain. Use AgentLang.

        
Loose AgentLang for API dataWrong choice: unvalidated, a tool cannot schema-check it. Convert with to-json first.

        
Secret in AgentLangblocked: reason=secret-pattern | need=public-pack-only — email, private-key block, key prefix, key/password assignment, or bearer token.

        
Secret in JSONBlocked the same way — the language does not make a secret safe. Never put a key, token, password, or personal identifier in either.

        
Invented field or fake proofblocked: reason=proof-none-cannot-resolve | need=proof-not-none — if proof is none, say proof=none, do not dress it up.

        
Code execution outside the sandboxNot built: no live model calls, no key fields, no plugin or tool loading from URLs, no code execution beyond Workshop sandboxed JS.

codebook-short

      

        
Fields (code=value, separated by ;, one line, header ac:1)a=agent | ro=role | t=task | s=status | x=ctx | i=in | o=out | v=verdict | f=conflict | n=next | d=done | b=blocked | y=verify | nt=note

        
Status (s)td=todo | dg=doing | vf=verify | dn=done | bl=blocked

        
Proof (inside v=model:claim:proof-code)cd=code | lv=live | ts=test | nn=none (unproven — say so, never dress it up; nn cannot resolve a conflict)

        
End-state ruleLast field must be exactly one of n (next, status td/dg/vf), d (done, status dn), b (blocked, status bl) — except compact end-state: status dn/bl with no terminal field, as in a Cloud single-line pack.

        
Reason codes (for b)not-ac | missing-agent | missing-task | missing-status | status-not-legal | terminal-missing | terminal-status-mismatch | secret-pattern | proof-none-cannot-resolve | field-not-code-equals | verdict-malformed | blocked-malformed — reported as blocked: reason=CODE | need=VALUE, exactly as AgentLang.

        
ValuesIdentifiers and kebab-case tokens only, no sentences, no spaces around ; or =. A sentence belongs in an al:1 note or a linked artifact, referenced by id here. Unknown codes are ignored with a warning, they do not fail the whole record.
